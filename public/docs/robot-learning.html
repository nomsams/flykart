Give the fly a task, then measure what it learns

Place the robot and furniture, add sugar or draw a trail, inspect its actual camera inputs, and compare repeatable runs. The simulator uses your camera, sonar, motor adapter and applied Arduino-style sketch. Learning controls extend this workbench; pretrained eyes and the native spiking brain remain separate.

Place, move and rotate

  1. Select an entity in the scene or object list. Choose Move and drag it across the floor. Choose Rotate and drag around its centre, or use the 15° buttons.
  2. The inspector accepts exact positions and rotations in degrees. Robot edits also set the reset and training start pose. A placement overlapping a solid at chassis height is rejected. Tables and chairs retain their separate legs and elevated tops.
  3. Choose Draw trail on floor and drag a path, or create a short demonstration trail. A stroke far from the old endpoint starts a replacement trail; Clear trail removes it. Undo restores the preceding layout, robot placement and objectives.

Sugar, trails and learned steering

Choose Explore, Find sugar, or Follow the trail to sugar. Sugar markers are magenta and nonblocking; their inspector exposes position, rotation, reward amount and collection radius. A target pays once per episode. Cyan trail checkpoints pay in sequence, and a contact penalty applies on entering a blocked state. Reset pickups restarts the evaluator while keeping learned weights.

The evaluator uses the true simulated position to detect reward events. That position, goal coordinates and checkpoint coordinates are absent from camera-based steering inputs. The fly receives an observable magenta/cyan pixel cue, or an explicitly enabled virtual scent signal. Rewards appear in the copyable console, training summaries and labelled evaluation data.

Fly + sugar memory steering combines the imported spiking output with a small mushroom-body-inspired association table: sparse visual Kenyon activations → three left/forward/right output values. Recent choices retain a decaying eligibility trace; sugar strengthens those connections and contact penalties weaken them. A simple colour cue and optional random exploration guide early attempts. This is an engineered learning model, not an anatomical reconstruction or a demonstrated biological navigation capability.

Live runs can learn from fly or manual steering demonstrations. The Learn checkbox freezes reward updates for comparisons. During seeded training the reward table is frozen for every candidate, visual memory resets, and evolution adjusts the native spiking controller. Score combines exploration, movement and objective reward with contact, blocked-time and cable penalties. The reward table and the evolutionary controller are distinct mechanisms.

Two different trail sensors

Painted trails and sugar markers are seen through the camera. Virtual pheromones are a local Gaussian scent field sampled by three simulated antennae, with adjustable width and decay. The scent overlay is hidden from camera capture. This adds a sensor the real car does not have: HC-SR04 and ESP32-CAM cannot measure pheromones. USB arming rejects virtual scent mode.

Memory capacity and recall

New labs start with 4,096 Kenyon cells at 1% activity. Choose 512, 2,048, 4,096, 10,000 or 20,000 cells and adjust sparsity. The display distinguishes currently active cells from cells with observations, reports occupancy and recall confidence, and makes crowding visible.

Memory stores graded observation counts and visual prototypes rather than a single taught bit. Optional rare-cell weighting reduces the influence of frequently activated cells. Visual recall uses camera features and past visual estimates; the separate sonar map uses command odometry and uncertain echo readings. This is not a GPS map, SLAM system or semantic room reconstruction. Applying different vision or memory settings resets both visual and reward memories because their representation changes. Legacy version-1 exports retain their original 512-cell projection and 16-cell activity when loaded.

What the source guides support

The requested sources were read in order: faces and compound vision, then maze navigation and memory. The inspected source snapshot was e0c8b97ffda12bbaadf28630bdaf147a8d2ba4e8.

The faces guide's useful transfer idea is diversity of gaze: distinct looks and weighted decisions, rather than assuming identical clones or arbitrary extra cells improve recognition. The maze guide motivates sparse graded memory, attention to saturation, rare-cell weighting, contrast normalization and averaging real frames in noisy conditions. Its larger memory and edge-processing experiments did not establish a universal advantage. Reward-only steering was unsuccessful in the reported maze tests, and scent trails were not tested there. This lab exposes those experiments for measurement and does not borrow their scores as evidence for this robot.

A forward camera near the floor differs from the maze guide's downward, north-up views. No north-up landmark map, route-sequence odometry belief, face classifier, hard-example boosting pipeline or new CNN training is implemented by these controls. The 2D robot work and its pretrained weights are preserved. Sensor-to-3D transfer and physical driving still need separate evaluation.

Source revision: e0c8b97, inspected from the flyfy repository on 4 October 2026. Guide results are simulation findings, not measurements of this chassis.

Export, reload and USB

Export lab preserves objects, floor, objectives, start pose, wiring, sketch, brain, eyes, memory and reward weights. Importing a lab starts the robot at the saved start pose. Export fly + eyes keeps the normal combined-brain format and adds a robotLearning extension for this workbench's visual settings, Kenyon memory and learned reward table. Other labs may ignore that extension. Use the full lab export to retain task layout and placement.

The USB bridge runs the host browser's eyes, filters, swarm, motor adapter and applied sketch on real camera and sonar frames. Exported reward weights can steer toward visible coloured cues. Physical sugar collection and reward updates are absent because no taste/reward feedback sensor is attached. Neural inference remains browser-hosted; flashing the bridge does not put the fly onto the ESP32. Serial safety timeouts and firmware pin-map checks remain active.

Start with a simple empty floor, a visible sugar marker and a short trail. Keep baseline settings, measure several fixed seeds, and change one setting at a time. Compare held-out room layouts and inspect copied logs and exported input frames before deciding an option helps.
